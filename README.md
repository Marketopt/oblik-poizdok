# Облік поїздок — Stage 2 (iPhone Edition)

React 18 + TypeScript + Vite. Україномовний мобільний інтерфейс, розрахунки відряджень, IndexedDB, резервні копії JSON, офлайн-PWA та іконка Time Growth.

## Локальний запуск і збірка

Потрібні Node.js 20.19+ або 22.12+ і npm. У папці `trip-app`:

```bash
npm install
npm run dev
npm run build
npm run preview
```

`npm run build` створює `dist/` для публікації. Розмістіть **вміст** `dist/` на HTTPS-хостингу в корені сайту (або налаштуйте Vite `base` і відповідні шляхи іконок для підкаталогу). Для iPhone PWA потрібно відкрити HTTPS-сайт у Safari, натиснути «Поділитися» → «На Початковий екран» → «Додати». Після першого успішного завантаження й активації service worker застосунок може відкриватися без інтернету. Перевіряйте офлайн-режим у встановленому застосунку.

## Можливості

- Вкладки «Введення», «Історія», «Звіт», «Підсумок»; пароль для підсумку і налаштувань (початковий порожній PIN).
- Календар із понеділка, дата DD/MM/YY; автокапіталізація назв міст.
- Кілометраж і ціна пального необов'язкові разом, але за наявності кілометражу ціна обов'язкова; витрата за замовчуванням 8 л/100 км.
- Час із кроком 30 хвилин; будні: до 08:00, після 18:00 і бонус 1 година; вихідні: вся тривалість.
- Готель, історія, редагування та видалення записів.
- Звітні періоди з редагованою кінцевою датою, текст для копіювання.
- Підсумок: зарплата, 130% компенсації пального, оплата понаднормових за ставкою зарплата / робочі дні / 8, готель.
- IndexedDB для локального зберігання поїздок і налаштувань, експорт та імпорт JSON через «Файли» на iPhone.
- PWA manifest, Apple Touch Icon, service worker з кешуванням оболонки застосунку.

## Важливі обмеження

- **Це локальна база на конкретному пристрої**. Видалення PWA, очищення даних Safari або системне очищення можуть видалити записи. Регулярно експортуйте JSON у «Файли» або iCloud Drive.
- Початковий пароль — лише локальний екранний захист; дані в IndexedDB **не зашифровані**. Не використовуйте для конфіденційних даних без додаткового шифрування.
- Імпорт JSON **повністю замінює** записи та налаштування після підтвердження.
- Service worker оновлюється після публікації нової версії; для повного офлайн-кешу потрібне перше успішне завантаження з інтернетом.
- Stage 2 не містить хостингу, App Store-пакета або синхронізації між пристроями.

## Структура

`src/main.tsx` — інтерфейс, `src/logic.ts` — розрахунки, `src/storage.ts` — IndexedDB і перевірка резервних копій, `src/style.css` — стилі, `public/sw.js` — офлайн-кеш, `public/manifest.webmanifest` — PWA, `public/icons/` — іконки.

## PIN-код (оновлення)
PIN-код містить рівно шість цифр. Для попередніх установок з восьмизначним паролем при оновленні PIN скидається, і користувач створює власний при першому відкритті налаштувань (дані поїздок зберігаються). Резервні копії зі старим тестовим паролем `12345678` також імпортуються зі скиданням PIN до порожнього. Це екранний захист, не шифрування.

## Перше налаштування PIN
Початковий PIN порожній. Під час першого відкриття налаштувань користувач двічі вводить власний шестизначний цифровий PIN. Після цього PIN захищає налаштування та підсумок. Старі невалідні PIN автоматично скидаються без видалення поїздок. PIN — екранний захист, а не шифрування.
